# Omsk Admissions Portal

Ниже — ТЗ, рассчитанное именно на максимально близкое воспроизведение страницы по приложенному скриншоту, а не просто «похожий дизайн». За эталон принимаем изображение 1910×995 px. Верхние ~37 px — интерфейс браузера, он не входит в верстку сайта.

Техническое задание: копия страницы «Электронные сервисы Приемной комиссии ОмГУ»

1. Цель

Разработать статическую/динамическую веб-страницу, визуально совпадающую с предоставленным скриншотом на desktop-разрешении.

Основной эталон:

ширина скриншота: 1910 px;

высота скриншота: 995 px;

высота браузерной панели на скриншоте: около 37 px;

фактическая видимая область страницы: примерно 1910 × 958 px;

масштаб браузера: считать 100%;

devicePixelRatio: для pixel-perfect проверки считать 1.

Приоритет при реализации:

геометрия → размеры → переносы текста → изображения → цвета → шрифты → интерактивность.

При этом globe и login должны быть SVG/иконками, а не emoji.

Все элементы белые.

Приблизительный стиль:

.nav {
  margin-left: auto;

  display: flex;
  align-items: center;
  height: 100%;
}

.nav__link {
  color: #fff;
  text-decoration: none;

  font-size: 14px;
  line-height: 1;
  font-weight: 600;

  white-space: nowrap;
}


Расстояния не должны быть одинаковыми автоматически через space-between. Лучше задавать фиксированные margin-left, чтобы добиться совпадения со скриншотом.

Ориентировочно:

.nav__link + .nav__link {
  margin-left: 32px;
}


Для отдельных элементов расстояния затем корректируются по overlay-сравнению.

16. Рекомендуемая сетка

Для получения максимально похожего результата desktop-версию лучше реализовать примерно так:

.services-grid {
  width: 1140px;
  margin: 0 auto;
  padding-top: 107px;

  display: grid;
  grid-template-columns: repeat(3, 380px);
  grid-template-rows: auto auto;
  row-gap: 88px;
}

.service {
  width: 380px;
}


Однако row-gap необходимо подгонять не по верхнему элементу, а так, чтобы вторая группа изображений начиналась на позиции около:

612px от начала страницы


Иными словами, pixel-perfect версия может потребовать индивидуального margin-top для второго ряда, поскольку первый ряд имеет блоки разной высоты.

Например:

.row-two {
  margin-top: 86px;
}


17. Иллюстрации

Это один из важнейших пунктов.

Чтобы получить реальное 1:1, нельзя заменить основные картинки просто «похожими иконками» из Font Awesome.

Необходимо получить пять конкретных изображений:

заявление/документ;

монитор + смартфон;

смартфон + шестеренка;

смартфон + шестеренка;

глобус + лупа.

Стиль:

stroke illustration;

практически без заливки;

серый контур;

тонкие линии;

небольшие декоративные плюсы;

отдельные мелкие детали.

Оптимальный формат:

SVG


Не использовать WebP/JPG для этих иллюстраций, если доступна возможность их перерисовать в SVG.

Для буквального совпадения со скриншотом допустим промежуточный вариант — извлечь графику из изображения и использовать PNG, но для production правильнее трассировать ее в SVG.

22. Hover

На самом скриншоте hover не показан, поэтому hover не должен влиять на визуальный baseline.

Допустимо:

a:hover {
  opacity: 0.85;
}


Но нельзя:

увеличивать карточку;

добавлять сильную тень;

менять размеры текста;

двигать элементы;

добавлять фон.

24. Что нельзя делать при реализации

Если требуется именно визуальная копия, не следует:

использовать Bootstrap Card;

делать серый фон страницы;

помещать сервисы в рамки;

добавлять border-radius;

добавлять тени карточкам;

применять большие hover-анимации;

использовать случайные Material Icons вместо исходных иллюстраций;

использовать emoji;

автоматически перераспределять карточки через space-around;

позволять тексту переноситься иначе, чем на эталоне;

менять высоту header;

растягивать main-контейнер на всю ширину экрана.
